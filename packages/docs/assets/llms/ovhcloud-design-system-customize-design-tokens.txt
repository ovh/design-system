# Design Tokens

Design tokens define reusable design values such as colors, borders, and outlines as variables. Instead of using hardcoded values, they provide a consistent, scalable, and maintainable way to style components across all products.

## Usage

Design tokens are available as CSS custom properties (variables) and can be used in your CSS files:

```css
.my-component {
  color: var(--ods-semantic-color-content-brand);
  border-radius: var(--ods-semantic-size-radius-control);
}
```

## Token types

Two types of tokens are meant to be used in your code:

- **Semantic**, `--ods-semantic-<category>-<role>` (e.g. `--ods-semantic-color-content-text`): values with a role, to style your own components and pages.
- **Component**, `--ods-<component>-<property>` (e.g. `--ods-button-background-color-primary`): values of a single ODS component, to customize it.

**Semantic** tokens give a role to a value: the color of a text, of a surface, of a border, the radius of a control, the duration of an animation…
Their name reads from the most generic to the most specific part, for example `--ods-semantic-color-surface-selected-solid` is a `color`, used as a `surface`, for a `selected` element, on a `solid` background.

**Component** tokens are declared by each component and default to semantic tokens.
Override them to adjust one component without affecting the others, see [Style Customization](https://ovh.github.io/design-system/v19.7.3/guides/style-customization).

## Which type should I use?

Prefer **semantic** tokens in your application: they follow the theme, so your components stay consistent with ODS ones when the theme changes.

Use **component** tokens only to customize an ODS component; never read them to style something else, as their value may change from one version to another.

## What is guaranteed

The `--ods-semantic-*` tokens are the public surface of the theme: read them in your CSS, re-declare them in a theme. Their names and their meaning do not change during a major version; their values belong to the theme. The `--ods-palette-*` ramps are public too, as the input of a theme: a brand re-declares the `--ods-palette-brand-*` and `--ods-palette-accent-*` ramps. The tables below list every token of the default theme.
