# Tailwind CSS Integration

This guide covers how to use Tailwind CSS utilities with the OVHcloud Design System (ODS) design tokens.

Tailwind CSS is not mandatory: ODS is not based on it, and `@ovhcloud/ods-react` does not depend on it. `@ovhcloud/ods-tailwind` is an opt-in package for the apps that use Tailwind CSS v4: it maps the Tailwind utilities to the ODS semantic tokens, so that `bg-ods-surface-raised` or `rounded-ods-container` read the same values as the ODS components.

## Installation

`@ovhcloud/ods-tailwind` requires Tailwind CSS v4.

```bash
npm install @ovhcloud/ods-tailwind tailwindcss @tailwindcss/vite
```

Add the Tailwind plugin of your bundler, for instance with Vite:

```typescript
// vite.config.ts
import tailwindcss from '@tailwindcss/vite';
import react from '@vitejs/plugin-react';
import { defineConfig } from 'vite';

export default defineConfig({
  plugins: [react(), tailwindcss()],
});
```

Then import `@ovhcloud/ods-tailwind` in your stylesheet, followed by the ODS theme. It brings Tailwind CSS itself: do not import `tailwindcss` again.

```css
/* index.css */
@import '@ovhcloud/ods-tailwind';
@import '@ovhcloud/ods-themes/default/css';
@import '@ovhcloud/ods-themes/default/fonts';
```

### Import order

Import this stylesheet **before any ODS component**, as the first import of your entry point:

```typescript
// main.tsx
import './index.css';
import { createRoot } from 'react-dom/client';
import { App } from './App';
```

  

  
> `@ovhcloud/ods-tailwind` declares the order of the CSS layers: the Tailwind theme, base and components, then the ODS layers, then the Tailwind utilities. The first stylesheet that names a layer sets its place. If an ODS component is imported before it, the ODS layers land before the Tailwind base styles, which then reset the ODS buttons and headings.

With this order, a utility you put on an ODS component wins over its style, and the ODS styles win over the Tailwind base styles.

A utility is named after its token: `--ods-semantic-color-surface-raised` gives `bg-ods-surface-raised`, `--ods-semantic-size-space-gap-group` gives `gap-ods-gap-group`. See [Design Tokens](https://ovh.github.io/design-system/v19.7.3/guides/design-tokens) for what each token is for. The palette (`--ods-palette-*`) is not mapped: use the semantic tokens, the ones a theme re-points.

```tsx
import { BADGE_STATUS, Badge, TEXT_PRESET, Text } from '@ovhcloud/ods-react';

function Summary() {
  return (
    <section className="flex flex-col gap-ods-gap-block rounded-ods-container border border-ods-border-container bg-ods-surface-raised p-ods-gap-group">
      <Text preset={ TEXT_PRESET.heading3 }>Your order</Text>
      <Badge status={ BADGE_STATUS.success }>Ready</Badge>
    </section>
  );
}
```

On a solid ground, use the content token made for it: `bg-ods-surface-brand` goes with `text-ods-content-on-brand-solid`.

## Themes

The utilities read the ODS tokens (`var(--ods-semantic-…)`), never their values. The same classes follow the theme you load: the default theme, Blue Jeans, their dark themes, or your own (see [Get Started](https://ovh.github.io/design-system/v19.7.3/guides/get-started) for the theme imports).

```css
/* index.css, with the Blue Jeans dark theme */
@import '@ovhcloud/ods-tailwind';
@import '@ovhcloud/ods-themes/default/css';
@import '@ovhcloud/ods-themes/blue-jeans/css';
@import '@ovhcloud/ods-themes/blue-jeans-dark/css';
@import '@ovhcloud/ods-themes/default/fonts';
```

### Switch themes at runtime

ODS ships no theme switcher, but each theme is an overlay that re-declares the semantic tokens on `:root`: loading or removing it switches the whole page, the ODS components and the Tailwind utilities alike, with no rebuild. For instance, with Vite, import the overlays as strings and add the one the user picks:

```tsx
import aluminiumDarkCss from '@ovhcloud/ods-themes/aluminium-dark/css?inline';
import { useEffect } from 'react';

function useDarkTheme(dark: boolean) {
  useEffect(() => {
    if (!dark) {
      return;
    }
    const style = document.createElement('style');
    style.textContent = aluminiumDarkCss;
    document.head.append(style);
    return () => style.remove();
  }, [dark]);
}
```

Add the overlay after the stylesheets of your app, so that it comes after the default theme. For Blue Jeans dark, add the Blue Jeans theme first, then its dark theme.

### Without the layer order

If your app already sets its own Tailwind entry point and layer order, import only the utilities, after Tailwind:

```css
@import 'tailwindcss';
@import '@ovhcloud/ods-tailwind/theme.css';
```

Then keep the ODS layers (`ods-quarks`, `ods-atoms`, `ods-molecules`, `ods-organisms`) after the Tailwind `base` layer and before `utilities` in your own `@layer` statement.

## Tailwind CSS v3

`@ovhcloud/ods-tailwind` requires Tailwind CSS v4. With Tailwind CSS v3, map the tokens you need in your `tailwind.config.js`, under the same names:

```js
/** @type {import('tailwindcss').Config} */
export default {
  content: ['./index.html', './src/**/*.{js,ts,jsx,tsx}'],
  theme: {
    extend: {
      borderRadius: {
        'ods-container': 'var(--ods-semantic-size-radius-container)',
        'ods-control': 'var(--ods-semantic-size-radius-control)',
      },
      colors: {
        'ods-border-container': 'var(--ods-semantic-color-border-container)',
        'ods-content-heading': 'var(--ods-semantic-color-content-heading)',
        'ods-surface-raised': 'var(--ods-semantic-color-surface-raised)',
      },
      fontFamily: {
        'ods-body': 'var(--ods-semantic-font-family-body)',
      },
    },
  },
};
```

Tailwind CSS v3 has no layer order of its own to declare: its base styles do not use cascade layers, so they win over the ODS styles. Leave the Tailwind preflight out (`corePlugins: { preflight: false }`) if it resets the ODS components.
