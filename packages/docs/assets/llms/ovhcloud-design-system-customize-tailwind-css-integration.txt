# Tailwind CSS Integration

This guide covers how to integrate Tailwind CSS with the OVHcloud Design System (ODS) for both v3 and v4 versions.

Tailwind CSS is a utility-first CSS framework that can be integrated with ODS components and design tokens, but it is not mandatory as ODS is not based on Tailwind.

  
  
> Technically, you don't need any configuration to make ODS work with Tailwind.
> These guides are here to add some auto-completion and best practices when using Tailwind,
> but you can directly use the design tokens right out of the box without any additional configuration.

## Tailwind CSS v3 Configuration

For Tailwind CSS v3, create a `tailwind.config.js` which contains a remapping of ODS variables:

```js
/** @type {import('tailwindcss').Config} */
export default {
  content: [
    "./index.html",
    "./src/**/*.{js,ts,jsx,tsx}",
  ],
  theme: {
    extend: {
      borderRadius: {
        'ods-control': 'var(--ods-semantic-size-radius-control)',
        'ods-container': 'var(--ods-semantic-size-radius-container)',
        'ods-pill': 'var(--ods-semantic-size-radius-pill)',
      },
      colors: {
        'ods-brand': 'var(--ods-semantic-color-surface-brand)',
        'ods-critical': 'var(--ods-semantic-color-surface-critical)',
        'ods-heading': 'var(--ods-semantic-color-content-heading)',
        'ods-success': 'var(--ods-semantic-color-surface-success)',
        'ods-text': 'var(--ods-semantic-color-content-text)',
        'ods-warning': 'var(--ods-semantic-color-surface-warning)',
      },
      fontFamily: {
        'ods-body': 'var(--ods-semantic-font-family-body)',
        'ods-code': 'var(--ods-semantic-font-family-code)',
      },
    },
  },
  plugins: [],
}
```

Then import the ODS theme as usual (see [Get Started](https://ovh.github.io/design-system/v19.7.3/guides/get-started)). Tailwind CSS v3 emits its utilities outside of any CSS layer, so they take precedence over the ODS component styles, which sit in the `ods-*` layers: a `rounded-ods-pill` class on an ODS component applies without further setup.

## Tailwind CSS v4 Configuration

For Tailwind CSS v4, create a CSS file using the [@theme](https://tailwindcss.com/docs/adding-custom-styles) property:

```css
/* ods-tailwind.css */
@theme {
  --radius-ods-control: var(--ods-semantic-size-radius-control);
  --radius-ods-container: var(--ods-semantic-size-radius-container);
  --radius-ods-pill: var(--ods-semantic-size-radius-pill);

  --color-ods-brand: var(--ods-semantic-color-surface-brand);
  --color-ods-critical: var(--ods-semantic-color-surface-critical);
  --color-ods-heading: var(--ods-semantic-color-content-heading);
  --color-ods-success: var(--ods-semantic-color-surface-success);
  --color-ods-text: var(--ods-semantic-color-content-text);
  --color-ods-warning: var(--ods-semantic-color-surface-warning);

  --font-ods-body: var(--ods-semantic-font-family-body);
  --font-ods-code: var(--ods-semantic-font-family-code);
}
```

Then import that file after Tailwind CSS and the ODS theme:

```css
/* index.css */
@layer theme, base, components, ods-quarks, ods-atoms, ods-molecules, ods-organisms, utilities;
@import "tailwindcss";
@import "@ovhcloud/ods-themes/default/css";
@import "@ovhcloud/ods-themes/default/fonts";
@import "./ods-tailwind.css";
```

The first line orders the CSS layers. Tailwind CSS v4 puts its utilities in the `utilities` layer and the ODS components put their styles in the `ods-*` layers: listing the `ods-*` layers before `utilities` lets a Tailwind class take precedence over an ODS component style. Without it, the `ods-*` layers come after the Tailwind ones, and the ODS styles win. The `base` layer, the Tailwind CSS reset, is optional.

## Themes and dark mode

The `ods-*` classes only read the ODS tokens, so they follow the theme the page loads, dark themes included: load another theme, or switch themes as explained in [Themes](https://ovh.github.io/design-system/v19.7.3/guides/themes), and they change with it, with no Tailwind CSS configuration and no `dark:` variant.

Other themes are imported after the default theme, as without Tailwind CSS. For instance, for the Blue Jeans theme in Tailwind CSS v4:

```css
/* index.css */
@layer theme, base, components, ods-quarks, ods-atoms, ods-molecules, ods-organisms, utilities;
@import "tailwindcss";
@import "@ovhcloud/ods-themes/default/css";
@import "@ovhcloud/ods-themes/default/fonts";
@import "@ovhcloud/ods-themes/blue-jeans/css";
@import "./ods-tailwind.css";
```

If your own classes use the `dark:` variant of Tailwind CSS, make it follow the same switch as the ODS dark theme. By default, it follows the color scheme of the operating system, as a dark theme loaded with `media="(prefers-color-scheme: dark)"` does. If your code turns the dark theme on and off, also set a class of your own on `<html>`, `ods-dark` for instance, and point the variant at it:

```css
/* Tailwind CSS v4, in index.css */
@custom-variant dark (&:where(.ods-dark, .ods-dark *));
```

```js
// Tailwind CSS v3, in tailwind.config.js
export default {
  darkMode: ['selector', '.ods-dark'],
  // …
}
```

ODS itself reads no class: `ods-dark` only drives your `dark:` classes.

## Integration with IDEs

### Integration with JetBrains

This should work straight out of the box.

### Integration with VSCode

Install the [Tailwind CSS IntelliSense](https://marketplace.visualstudio.com/items?itemName=bradlc.vscode-tailwindcss) extension: the `ods-*` classes complete from your configuration (v3) or your CSS file (v4). In Tailwind CSS v4, if the extension does not find your CSS file, point its `tailwindCSS.experimental.configFile` setting at it.

## Usage Examples

You can use Tailwind utilities alongside ODS components:

```tsx
import { Button } from '@ovhcloud/ods-react';

function MyComponent() {
  return (
    <div>
      <p className="text-ods-heading font-ods-body">Click on the button!</p>
      <Button className="rounded-ods-pill">Click me!</Button>
    </div>
  );
}
```

## Best Practices & Troubleshooting

### Color Usage

- Use semantic color names (e.g., `ods-brand`, `ods-success`) instead of generic colors
- **Issue**: Color classes not working? Verify that the Tailwind config (v3) or the `@theme` file (v4) includes the ODS color mappings, and that the content paths (v3) include your component files.

### Spacing and Layout

- Use ODS border radius tokens (`rounded-ods-control`, `rounded-ods-container`, etc.)
- **Issue**: CSS variables not loading? Ensure `@ovhcloud/ods-themes/default/css` is imported, and loaded before the other themes.

### Typography

- Use the ODS font family (`font-ods-body` for body text, `font-ods-code` for code)
- Apply semantic text colors (`text-ods-text`, `text-ods-heading`)
- Maintain proper contrast ratios with ODS color combinations

### Component Integration

- ODS components can be styled with Tailwind utilities using the `className` prop
- Avoid overriding core ODS component styles unless necessary
- Use Tailwind for layout and positioning, ODS for component behavior
- **Issue**: An ODS style wins over a Tailwind class in v4? Check that the `@layer` line comes first in your CSS entry file.
- **Issue**: Responsive breakpoints not matching ODS? The ODS breakpoints are Sass variables of `@ovhcloud/ods-react/style` (`$ods-breakpoint-mobile: 576px`, `$ods-breakpoint-tablet: 768px`, `$ods-breakpoint-desktop: 992px`, `$ods-breakpoint-large-screen: 1200px`), not CSS custom properties: declare their values in `theme.screens` (v3) or as `--breakpoint-*` variables in `@theme` (v4).
