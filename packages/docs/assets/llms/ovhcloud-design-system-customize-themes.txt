# Themes

A theme is a stylesheet that declares the ODS design tokens as CSS custom properties on `:root`. ODS components read these tokens, and so can your own CSS: load a theme, and both follow it.

## Available themes

`@ovhcloud/ods-themes` ships four themes:

- **Default** (`@ovhcloud/ods-themes/default/css`), the Aluminium look: the base every other theme is loaded after.
- **Blue Jeans** (`@ovhcloud/ods-themes/blue-jeans/css`), the OVHcloud look, an overlay on the default theme.
- **Aluminium dark** (`@ovhcloud/ods-themes/aluminium-dark/css`), the dark overlay of the default theme.
- **Blue Jeans dark** (`@ovhcloud/ods-themes/blue-jeans-dark/css`), the dark overlay of the Blue Jeans theme.

The fonts are a stylesheet of their own, `@ovhcloud/ods-themes/default/fonts`, for every theme.

## Load a theme

An overlay only re-declares the tokens it changes, so it is loaded **after** the theme it builds on. Every theme declares its tokens on `:root`, with the same specificity: the stylesheet loaded last wins.

The default theme:

```typescript
import '@ovhcloud/ods-themes/default/css';
import '@ovhcloud/ods-themes/default/fonts';
```

The Blue Jeans theme:

```typescript
import '@ovhcloud/ods-themes/default/css';
import '@ovhcloud/ods-themes/default/fonts';
import '@ovhcloud/ods-themes/blue-jeans/css';
```

The Aluminium dark theme:

```typescript
import '@ovhcloud/ods-themes/default/css';
import '@ovhcloud/ods-themes/default/fonts';
import '@ovhcloud/ods-themes/aluminium-dark/css';
```

The Blue Jeans dark theme:

```typescript
import '@ovhcloud/ods-themes/default/css';
import '@ovhcloud/ods-themes/default/fonts';
import '@ovhcloud/ods-themes/blue-jeans/css';
import '@ovhcloud/ods-themes/blue-jeans-dark/css';
```

## Switch themes

A page shows one theme: the one its stylesheets declare on `:root`. No attribute or class selects a theme, so ODS does not switch themes by itself.

To switch themes, change the stylesheets the page loads. The order still matters, so keep each overlay in its own `<link>` after the theme it builds on, and turn it on or off:

```html
<link rel="stylesheet" href="/ods-themes/default/index.css">
<link rel="stylesheet" href="/ods-themes/aluminium-dark/index.css" id="ods-dark" disabled>
```

```typescript
function setDarkMode(isDark: boolean): void {
  (document.getElementById('ods-dark') as HTMLLinkElement).disabled = !isDark;
}
```

To follow the color scheme of the operating system instead, without any script, give the dark overlay a media query:

```html
<link rel="stylesheet" href="/ods-themes/default/index.css">
<link rel="stylesheet" href="/ods-themes/aluminium-dark/index.css" media="(prefers-color-scheme: dark)">
```

These URLs assume the `dist` folder of `@ovhcloud/ods-themes` copied to your public folder as `ods-themes`, one folder per theme.

With Vite, a `?url` import emits the file and gives its URL instead. Vite adds the stylesheets you import after the `<link>` elements of your `index.html`, so an overlay declared there would come before the default theme and lose: create its `<link>` from your code, at the end of `<head>`:

```typescript
import '@ovhcloud/ods-themes/default/css';
import darkThemeUrl from '@ovhcloud/ods-themes/aluminium-dark/css?url';

const darkTheme = Object.assign(document.createElement('link'), { disabled: true, href: darkThemeUrl, rel: 'stylesheet' });
document.head.append(darkTheme);

function setDarkMode(isDark: boolean): void {
  darkTheme.disabled = !isDark;
}
```

This documentation also loads its overlays after the default theme, into two `<style>` elements that its theme select and its color scheme button fill.

## Use the tokens in your CSS

Style your own elements with the `--ods-semantic-*` tokens, and they follow the theme as the ODS components do. Switch the theme or the color scheme of this documentation, from its top bar (at the bottom of the navigation on narrow screens): the plan below follows, as its Button does. The two dark themes share their surfaces and their brand color, so the plan looks the same in both.

```tsx
<>
  <style>{`
    .my-plan {
      display: flex;
      flex-direction: column;
      gap: var(--ods-semantic-size-space-gap-block);
      max-width: 280px;
      padding: var(--ods-semantic-size-space-inset-block) var(--ods-semantic-size-space-inset-inline);
      border: var(--ods-semantic-border-thickness) solid var(--ods-semantic-color-border-container);
      border-radius: var(--ods-semantic-size-radius-container);
      background-color: var(--ods-semantic-color-surface-raised);
      color: var(--ods-semantic-color-content-text);
    }

    .my-plan__name {
      margin: 0;
      color: var(--ods-semantic-color-content-heading);
      font-weight: var(--ods-semantic-font-weight-semibold);
    }

    .my-plan__price {
      color: var(--ods-semantic-color-content-brand);
      font-weight: var(--ods-semantic-font-weight-bold);
    }
  `}</style>

  <div className="my-plan">
    <p className="my-plan__name">Starter plan</p>
    <span className="my-plan__price">€4.99 / month</span>
    <Button>Order</Button>
  </div>
</>
```

The [Design Tokens](https://ovh.github.io/design-system/v19.7.3/guides/design-tokens) page explains which tokens to use and lists all of them.

## Create your own theme

A theme of your own is an overlay too: a stylesheet, loaded after `@ovhcloud/ods-themes/default/css`, that re-declares the brand and accent ramps on `:root`, from `50` to `900`:

```css
:root {
  --ods-palette-brand-500: #7a00cc;
  /* and the other brand and accent rungs, from 50 to 900 */
}
```

The ramps do not reach every role: the focus ring, the information, success, warning, critical and neutral statuses, and the chart series keep their default values. Over the default theme alone, the brand ghost and outline Buttons also take their text from the accent ramp and their border from gray (`--ods-semantic-color-border-brand-minor`), which follows no ramp. Re-declare the `--ods-semantic-*` tokens themselves to change them. The [migration guide](https://ovh.github.io/design-system/v19.7.3/guides/migration-19-to-20) details which roles each ramp reaches.

The ramps only take effect on `:root`: a theme scoped to a container, such as the root of a micro-frontend, re-declares the `--ods-semantic-*` roles themselves.

With a dark overlay, load your theme between the default theme and the overlay. The overlay reads the brand and accent ramps, so your colors reach it, and the roles it re-declares, such as the focus ring, stay on top:

```typescript
import '@ovhcloud/ods-themes/default/css';
import '@ovhcloud/ods-themes/default/fonts';
import './my-theme.css';
import '@ovhcloud/ods-themes/aluminium-dark/css';
```
