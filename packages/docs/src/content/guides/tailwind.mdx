This guide covers how to use Tailwind CSS utilities with the OVHcloud Design System (ODS) design tokens.

Tailwind CSS is not mandatory: ODS is not based on it, and `@ovhcloud/ods-react` does not depend on it. `@ovhcloud/ods-tailwind` is an opt-in package for the apps that use Tailwind CSS v4: it maps the Tailwind utilities to the ODS semantic tokens, so that `bg-ods-surface-raised` or `rounded-ods-container` read the same values as the ODS components.

<Heading label="Installation" level={ 2 } />

`@ovhcloud/ods-tailwind` requires Tailwind CSS v4.

```bash
npm install @ovhcloud/ods-tailwind tailwindcss @tailwindcss/vite
```

Add the Tailwind plugin of your bundler, for instance with Vite:

```typescript
// vite.config.ts
import tailwindcss from '@tailwindcss/vite';
import react from '@vitejs/plugin-react';
import { defineConfig } from 'vite';

export default defineConfig({
  plugins: [react(), tailwindcss()],
});
```

Then import `@ovhcloud/ods-tailwind` in your stylesheet, followed by the ODS theme. It brings Tailwind CSS itself: do not import `tailwindcss` again.

```css
/* index.css */
@import '@ovhcloud/ods-tailwind';
@import '@ovhcloud/ods-themes/default/css';
@import '@ovhcloud/ods-themes/default/fonts';
```

<Heading label="Import order" level={ 3 } />

Import this stylesheet **before any ODS theme or component**, as the first import of your entry point, and import the ODS theme from it rather than from JavaScript:

```typescript
// main.tsx
import './index.css';
import { createRoot } from 'react-dom/client';
import { App } from './App';
```

<Message dismissible={ false } style={{ width: '100%' }}>
  <MessageIcon name="triangle-exclamation" />

  <MessageBody>
    `@ovhcloud/ods-tailwind` declares the order of the CSS layers: the Tailwind theme and base, then the ODS layers, then the Tailwind components and utilities. A layer takes its place from the first stylesheet that names it, and the ODS theme and components name the ODS layers too. If either is imported before `@ovhcloud/ods-tailwind`, the ODS layers land before the Tailwind base styles, which then reset the ODS buttons and headings.
  </MessageBody>
</Message>

With this order, the ODS styles win over the Tailwind base styles, and your own styles win over the ODS ones: a utility on an ODS component, or a rule of yours in `@layer components`, where Tailwind puts the styles of your components. Target an ODS element with a class rather than a tag selector there: a `.card button` rule in `@layer components` also restyles every ODS button of the card.

For an order that holds whatever the import order, declare it in the `<head>` of your page, before any stylesheet:

```html
<style>@layer theme, base, ods-quarks, ods-atoms, ods-molecules, ods-organisms, components, utilities;</style>
```

With a Content Security Policy, allow this inline style with its hash or a nonce.

A utility is named after its token: `--ods-semantic-color-surface-raised` gives `bg-ods-surface-raised`, `--ods-semantic-size-space-gap-group` gives `gap-ods-gap-group`. See <DocLink to="/guides/design-tokens">Design Tokens</DocLink> for what each token is for. The palette (`--ods-palette-*`) is not mapped: use the semantic tokens, the ones a theme re-points.

```tsx
import { BADGE_STATUS, Badge, TEXT_PRESET, Text } from '@ovhcloud/ods-react';

function Summary() {
  return (
    <section className="flex flex-col gap-ods-gap-block rounded-ods-container border border-ods-border-container bg-ods-surface-raised p-ods-gap-group">
      <Text preset={ TEXT_PRESET.heading3 }>Your order</Text>
      <Badge status={ BADGE_STATUS.success }>Ready</Badge>
    </section>
  );
}
```

On a solid ground, use the content token made for it: `bg-ods-surface-brand` goes with `text-ods-content-on-brand-solid`. `bg-ods-brand` is the brand color of the logo, not a surface.

The page font is the ODS body font, and the monospace font the ODS code font: the Tailwind base styles set them on the page, so the ODS components and their overlays (Modal, Popover, Tooltip…) inherit them with no class.

The tokens Tailwind has no theme for are not mapped. Read them with the variable shorthand: `z-(--ods-semantic-z-index-modal)`, `opacity-(--ods-semantic-opacity-disabled)`, `duration-(--ods-semantic-motion-duration-fast)`.

<Heading label="Themes" level={ 2 } />

The utilities read the ODS tokens (`var(--ods-semantic-…)`), never their values. The same classes follow the theme you load: the default theme, Blue Jeans, their dark themes, or your own (see <DocLink to="/guides/get-started">Get Started</DocLink> for the theme imports).

```css
/* index.css, with the Blue Jeans dark theme */
@import '@ovhcloud/ods-tailwind';
@import '@ovhcloud/ods-themes/default/css';
@import '@ovhcloud/ods-themes/blue-jeans/css';
@import '@ovhcloud/ods-themes/blue-jeans-dark/css';
@import '@ovhcloud/ods-themes/default/fonts';
```

To follow the system setting with no JavaScript, condition the dark theme on it:

```css
@import '@ovhcloud/ods-tailwind';
@import '@ovhcloud/ods-themes/default/css';
@import '@ovhcloud/ods-themes/aluminium-dark/css' (prefers-color-scheme: dark);
@import '@ovhcloud/ods-themes/default/fonts';
```

<Heading label="Switch themes at runtime" level={ 3 } />

ODS ships no theme switcher, but each theme is an overlay that re-declares the semantic tokens on `:root`: loading or removing it switches the whole page, the ODS components and the Tailwind utilities alike, with no rebuild. For instance, with Vite, import the overlays as strings and add the one the user picks:

```tsx
import aluminiumDarkCss from '@ovhcloud/ods-themes/aluminium-dark/css?inline';
import { useEffect } from 'react';

function useDarkTheme(dark: boolean) {
  useEffect(() => {
    document.documentElement.toggleAttribute('data-dark', dark);
    if (!dark) {
      return;
    }
    const style = document.createElement('style');
    style.textContent = aluminiumDarkCss;
    document.head.append(style);
    return () => style.remove();
  }, [dark]);
}
```

Add the overlay after the stylesheets of your app, so that it comes after the default theme. For Blue Jeans dark, add the Blue Jeans theme first, then its dark theme. With a Content Security Policy, allow inline styles with a nonce. The overlay applies once the page has rendered: to avoid a flash of the light theme, read the user's choice in a small inline script in the `<head>`.

The Tailwind `dark:` variant follows the system setting by default, not the theme you load. Point it at your switch, so that `dark:` utilities and the ODS dark theme go together:

```css
@custom-variant dark (&:where([data-dark], [data-dark] *));
```

<Heading label="Without the layer order" level={ 3 } />

If your app already sets its own Tailwind entry point and layer order, import only the utilities, after Tailwind, and after any reset of a namespace (`--color-*: initial`), which would clear the ODS utilities too:

```css
@import 'tailwindcss';
@import '@ovhcloud/ods-tailwind/theme.css';
```

Then keep the ODS layers (`ods-quarks`, `ods-atoms`, `ods-molecules`, `ods-organisms`) after the Tailwind `base` layer and before `components` in your own `@layer` statement.

<Heading label="Tailwind CSS v3" level={ 2 } />

`@ovhcloud/ods-tailwind` requires Tailwind CSS v4. With Tailwind CSS v3, map the tokens you need in your `tailwind.config.js`, under the same names:

```js
/** @type {import('tailwindcss').Config} */
export default {
  content: ['./index.html', './src/**/*.{js,ts,jsx,tsx}'],
  theme: {
    extend: {
      borderRadius: {
        'ods-container': 'var(--ods-semantic-size-radius-container)',
        'ods-control': 'var(--ods-semantic-size-radius-control)',
      },
      colors: {
        'ods-border-container': 'var(--ods-semantic-color-border-container)',
        'ods-content-heading': 'var(--ods-semantic-color-content-heading)',
        'ods-surface-raised': 'var(--ods-semantic-color-surface-raised)',
      },
      fontFamily: {
        'ods-body': 'var(--ods-semantic-font-family-body)',
      },
    },
  },
};
```

Tailwind CSS v3 has no layer order of its own to declare: its base styles do not use cascade layers, so they always win over the ODS styles and reset the ODS buttons and headings. Leave the Tailwind preflight out: `corePlugins: { preflight: false }`.
